# Postmark — AI Email Management for Personal Assistants

A prototype for the **AI Full-Stack Engineer Intern** assignment. Postmark helps a personal assistant manage a client's inbox and uses AI to decide **who needs to reply**. A separate, minimal view shows the client only what needs *their* personal attention.

**Stack:** Next.js 16 (React 19, Tailwind, shadcn/ui) · Node.js + Express · MongoDB (Mongoose) · Gemini API (any OpenAI-compatible API also works)

> 🎯 **Interview demo:** Start backend (`cd backend && npm start`), then frontend (`npm run dev`). Visit `http://localhost:3000` → Onboarding → Dashboard. Say *"Simulate new email"* to watch the AI classify live.

---

## ✨ Features

| Area | What it does |
|------|-------------|
| **Onboarding** | Sign-up/login choice, simulated Gmail/Outlook consent, animated sync (with optional "simulate failure" state) |
| **Assistant Dashboard** | Live stats, folders with counts, search, Unread/Starred/**Needs review** filters, classification chips with confidence |
| **AI Classification** | Per-sender rule → LLM → keyword fallback. Low confidence (< 70%) flagged as **Needs review** |
| **Manual Control** | Change any classification; "Corrected by you" badge; optional **"Teach the AI"** per-sender rule |
| **Client View** | Only *Client to Reply* emails, with summary and "Why you?". **Mark handled** / **Let my assistant take over** update assistant dashboard immediately |
| **Conversation** | Thread, AI summary, reason, deadlines, archive / important / unread / completed |
| **Draft Reply** | AI draft, edit, **review-and-confirm** before "sending" — never sent automatically |
| **Ask Your Inbox** | Chat answers questions like *"What am I waiting on?"* with clickable email cards |
| **Reply Radar** | Client-to-Reply emails with no reply for 48h+ get an orange *"Client quiet for N days"* badge, stat-card warning, and **Nudge client** button |
| **Teach the AI (Rules)** | Save a per-sender rule when correcting classification; manage in **Settings → AI classification rules**. Rules run before the AI |
| **Dark Mode** | Dark by default, with sun/moon toggle (bottom-right) that remembers choice. Colors in `app/dark-theme.css`, generated by `node scripts/gen-dark-theme.mjs` |
| **Keyboard Shortcuts** | **Ctrl/⌘ + K** focuses the search box |
| **Simulate New Email** | One click adds an incoming email and the AI classifies it live |

## ⚠️ What is Simulated

- Gmail / Outlook OAuth and email sync (sample data is used)
- Sending email (the confirm step shows success, nothing is sent)
- Client login (a link switches between the assistant and client views)

## 🚀 Quick Start

### Frontend Only (Demo Mode — No Backend Needed)
```bash
npm install     # or pnpm install
npm run dev     # http://localhost:3000
```
Runs in **demo mode**: sample emails stored in browser. Assistant and client views stay in sync. Use *Simulate new email* to try the classifier flow (rule-based in this mode).

---

### Full Stack (MongoDB + Real AI)

**Backend:**
```bash
cd backend
cp .env.example .env     # fill MONGODB_URI and LLM_API_KEY (.env.local also works)
npm install
npm run seed             # loads 12 sample threads
npm run dev              # http://localhost:5000
```

**Frontend (connect to backend):**
```bash
# In project root, create .env.local:
NEXT_PUBLIC_API_URL=http://localhost:5000
npm run dev              # http://localhost:3000
```

> **Notes:**
> - If Atlas fails with `querySrv ECONNREFUSED`, the backend switches to public DNS for `mongodb+srv://` URIs (set `USE_CUSTOM_DNS=false` to disable)
> - Get a free Gemini key at [Google AI Studio](https://aistudio.google.com) (Get API key). Key stays in `backend/.env` only
> - `LLM_MODEL` defaults to `gemini-flash-latest`; change if Google renames the model
> - To use Groq or another OpenAI-compatible API:
>   ```env
>   LLM_PROVIDER=openai
>   LLM_BASE_URL=...
>   LLM_MODEL=...
>   LLM_API_KEY=...
>   ```
> - If the LLM is down or rate-limited, classification, drafts, and chat fall back to rules/templates — the app never breaks

## 🚢 Deploy

A `render.yaml` blueprint for the backend is included.

1. **MongoDB Atlas** — Create free cluster, then run `npm run seed` once against it
2. **Render** (Web Service)
   - Root: `backend`
   - Build: `npm install`
   - Start: `npm start`
   - Env vars: `MONGODB_URI`, `LLM_API_KEY`, `LLM_MODEL`, `CLIENT_URL=<your Vercel URL>`
3. **Vercel** (Root of repo)
   - Env: `NEXT_PUBLIC_API_URL=<your Render URL>`
4. Free Render servers sleep — open `<render-url>/api/health` before demoing
