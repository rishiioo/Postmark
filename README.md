# Postmark — AI email management for personal assistants

A prototype for the **AI Full-Stack Engineer Intern** assignment. Postmark helps a personal assistant manage a client's inbox and uses AI to decide **who needs to reply**. A separate, minimal view shows the client only what needs *their* personal attention.

**Stack:** Next.js 16 (React 19, Tailwind, shadcn/ui) · Node.js + Express · MongoDB (Mongoose) · Gemini API (any OpenAI-compatible API also works)

> 🎯 **Interview demo:** Start backend (`cd backend && npm start`), then frontend (`npm run dev`). Visit `http://localhost:3000` → Onboarding → Dashboard. Say *"Simulate new email"* to watch the AI classify live.

## What works

| Area | What it does |
|---|---|
| Onboarding | Sign-up/login choice, simulated Gmail/Outlook consent, animated sync (with an optional "simulate failure" state) |
| Assistant dashboard | Live stats, folders with counts, search, Unread/Starred/**Needs review** filters, classification chips with confidence |
| AI classification | Per-sender rule → LLM → keyword fallback. Low confidence (< 70) is flagged **Needs review** |
| Manual control | Change any classification; "Corrected by you" badge; optional **"Teach the AI"** per-sender rule |
| Client view | Only *Client to Reply* emails, with a summary and "Why you?". **Mark handled** / **Let my assistant take over** update the assistant dashboard immediately |
| Conversation | Thread, AI summary, reason, deadlines, archive / important / unread / completed |
| Draft reply | AI draft, edit, **review-and-confirm** before "sending" — never sent automatically |
| Ask your inbox | Chat answers questions such as "What am I waiting on?" with clickable email cards |
| Reply Radar | Client-to-Reply emails with no reply for 48h+ get an orange "Client quiet for N days" badge, a stat-card warning and a **Nudge client** button |
| Teach the AI (rules) | Save a per-sender rule when you correct a classification; manage them in **Settings → AI classification rules**. Rules run before the AI |
| Dark mode | Dark by default, with a sun/moon toggle (bottom-right) that remembers your choice. Colours live in `app/dark-theme.css`, generated by `node scripts/gen-dark-theme.mjs` — re-run it after adding new colour classes |
| Keyboard | **Ctrl/⌘ + K** focuses the search box |
| Simulate new email | One click adds an incoming email and the AI classifies it live |

## What is simulated

- Gmail / Outlook OAuth and email sync (sample data is used)
- Sending email (the confirm step shows success, nothing is sent)
- Client login (a link switches between the assistant and client views)

## Run it

### Frontend (demo mode, no backend needed)
```bash
npm install     # or pnpm install
npm run dev     # http://localhost:3000
```
Without a backend the app runs in **demo mode**: sample emails are stored in your browser, so the assistant and client views still stay in sync. Use *Simulate new email* to try the classifier flow (rule-based in this mode).

### Backend (MongoDB + real AI)
```bash
cd backend
cp .env.example .env     # fill MONGODB_URI and LLM_API_KEY (.env.local also works)
npm install
npm run seed             # loads 12 sample threads
npm run dev              # http://localhost:5000
```
Then set `NEXT_PUBLIC_API_URL=http://localhost:5000` in a `.env.local` file in the project root and restart `npm run dev`.

- If Atlas fails with `querySrv ECONNREFUSED`, the backend already switches to public DNS for `mongodb+srv://` URIs (set `USE_CUSTOM_DNS=false` to disable).
- Get a free Gemini key at <https://aistudio.google.com> (Get API key). The key stays in `backend/.env` only.
- `LLM_MODEL` defaults to `gemini-flash-latest`; change it if Google renames the model.
- To use Groq or another OpenAI-compatible API: `LLM_PROVIDER=openai`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
- If the LLM is down or rate-limited, classification, drafts and chat fall back to rules/templates, so the app never breaks.

### API
`GET /api/threads` · `GET/PATCH /api/threads/:id` · `POST /api/threads/:id/classify` · `POST /api/threads/:id/draft` · `POST /api/threads/classify-all` · `POST /api/simulate-email` · `POST /api/chat` · `GET/POST/DELETE /api/rules` · `GET /api/health`

## Deploy
A `render.yaml` blueprint for the backend is included (set `MONGODB_URI`, `CLIENT_URL`, `LLM_API_KEY` in Render).

1. **MongoDB Atlas** free cluster, then run `npm run seed` once against it.
2. **Render** (Web Service, root `backend`, build `npm install`, start `npm start`). Env: `MONGODB_URI`, `LLM_API_KEY`, `LLM_MODEL`, `CLIENT_URL=<your Vercel URL>`.
3. **Vercel** (root of the repo). Env: `NEXT_PUBLIC_API_URL=<your Render URL>`.
4. Free Render servers sleep: open `<render-url>/api/health` before demoing.
